# P1 audit remediation — 23 September 2026

The targeted implementation and reporting defects have been corrected. This is a code/protocol remediation, **not a new claim of validated treatment benefit**. Production models, tuning studies and the 30-run benchmark have not been retrained in this task. Historical numerical results remain historical.

## Changes by audit finding

| Finding | Implemented correction | Evidence |
|---|---|---|
| M1 — ignored static inputs | New models initialize hidden/cell states from patient and pretreatment static features, and the initial treatment state from pretreatment history. Old checkpoints retain explicit legacy zero-state behavior. | Perturbation and gradient tests; checkpoint round trips; real-data forward pass with 16 patient and 17 treatment-history static inputs. |
| M2 — test used for selection | Separate training, development validation and temporal test patients. CV stays inside development data; all semisynthetic prefixes of one original patient stay together. Scaling and the survival grid use training data only. Test evaluation is opt-in after fitting. | Disjoint-group tests for final training/CV and random/temporal splits; held-out perturbations cannot change fitted scaling/grid; actual-cohort checks below. |
| M3 — missing Brier weights | Both per-subject and evaluation-time IPCW weights are supplied to TorchSurv in DynaSurv, Cox, DeepSurv and RSF. | Numerical regression test against a hand-calculated weighted Brier score. This repairs the API error, not every censoring assumption. |
| R1 — conditional propensities | Assignment models fit **all observed classes**. Eligibility is intersected afterwards, so a population mostly receiving excluded arms cannot acquire artificial overlap by renormalization. Rare/single-class folds are handled explicitly. | A 5% / 5% / 90% fixture correctly rejects the first two arms at a 10% floor; real fits retain 11/10/10/9 classes across lines. |
| R2 — singleton “confidence” | Added `ONLY_SUPPORTED_OPTION`. Its leader is identified, but `recommended_idx` is -1; comparative confidence requires at least two eligible arms. Exact ties remain undecided even at zero margin. | Decision-rule tests, exports and both recommendation/horizon CLI summaries updated. |
| R4 — shortened histories | Propensity prediction computes only the observed prefix and returns the matching shape. | Full-history versus prefix equivalence tests, including an end-to-end recommender test; actual-data one-line support call. |
| R8 — calibration misstatement | Persist and report calibration status. `bestCALIB` is epoch selection, not post-hoc fitting. Removed rank-preservation claims; the optional calibrator is explicitly experimental. | Checkpoint metadata and manuscript updates; mixed calibration states cannot enter the same checked ensemble. |
| S1 — double selection on evaluation | Separate grouped development validation from test. Aggregation takes a fixed `--kind`, never the minimum test oracle regret. The cluster sweep evaluates all kinds on validation and only prespecified `TEST_KIND` on test. | Aggregation regression tests, split tests, shell syntax and dry-run checks. Legacy tables require `--legacy-exploratory`. |
| S2 — transferred censoring weights | Primary simulation factual scores now use exact expected Brier loss and uncensored latent outcomes at the requested horizon, with no marginal training-KM transfer or silent horizon clipping. | Analytical fixture and reference-cohort numerical check below. |
| S3 — incomplete comparator conclusions | Added a full comparator summary covering curve/effect/policy/factual metrics, including KM PEHE. Manuscript and benchmark report explicitly separate historical ranking benefit from effect-estimation accuracy. | Regenerated historical comparison confirms worse DynaSurv mean pair PEHE in 9/10 cells, despite better reference policy regret. Corrected empirical comparisons still require retraining. |

Additional safeguards: exact duplicate patient-line rows are removed; conflicting duplicates fail loudly. Missing support fails closed. Dataset/schema/scaler/grid/split manifests are persisted in checkpoints and checked before ensemble evaluation. Old conditional-propensity checkpoints cannot silently enter corrected recommendations. New HPO studies refuse legacy or mismatched trials. Training refuses a directory already containing checkpoints.

## Migration and rerunning

Retraining is mandatory: old weights never learned the new static projections and were trained with different preprocessing/selection. The compatibility loader remains available for historical inspection, but corrected recommendation/evaluation entry points reject incompatible checkpoints.

The following commands are examples to run **from `scripts/`**, in the project environment. They have not been launched here. Select model/checkpoint rules using development data; do not switch them after viewing test oracle results.

1. Re-tune on the corrected development split. Defaults now use `optuna_study_v2.db`, study `dynasurv_hpo_v2` and output `hyperopt/best_config_v2.json`:

   ```sh
   PYTHONPATH=../src python hyperopt/run_optuna.py --data-dir ../data
   ```

2. Train new real-data ensemble members in a separate run root. Repeat with the chosen seed set; the validation partition stays fixed:

   ```sh
   PYTHONPATH=../src python TrainDynasurvCausal.py --seed 0 --model-config hyperopt/best_config_v2.json --run-root ../models/p1_real
   ```

   No test evaluation runs by default. `--evaluate-test` explicitly evaluates the configured checkpoint rule on test after fitting. Once enough compatible members exist:

   ```sh
   PYTHONPATH=../src python RecommendEnsemble.py --model-config hyperopt/best_config_v2.json --kind val_loss --runs '../models/p1_real/*_seed_*'
   ```

3. Retrain and score a semisynthetic cell using the same frozen model configuration:

   ```sh
   PYTHONPATH=../src python semisynthetic/train.py --axis gamma --level 1.0 --rep 0 --seed 0 --model-config hyperopt/best_config_v2.json
   PYTHONPATH=../src python semisynthetic/evaluate.py --axis gamma --level 1.0 --rep 0 --seed 0 --model-config hyperopt/best_config_v2.json --kind val_loss --split test
   PYTHONPATH=../src python semisynthetic/aggregate.py --kind val_loss --split test
   ```

   New runs default to `models/semisynthetic_v2`; new summaries to `reports/semisynthetic_sweep_v2`. The cluster sweep's default final test rule is `val_loss`; development checkpoint comparisons remain separate. Set `MODEL_CONFIG=hyperopt/best_config_v2.json` when submitting the cluster sweep to pass that same configuration to both training and evaluation (the path is interpreted from `scripts/` on the cluster).

## What remains scientifically unresolved

- Full new HPO, real-data training, benchmark reruns, and regenerated paper figures/tables are still required. Existing `configs/best_config.json` is not magically re-tuned by these edits.
- S3's measured underperformance is not something a reporting patch can remove. The missing comparator is now visible; richer Cox/Weibull/DeepSurv/history-aware comparisons and static/history/balancing ablations remain experiments to perform before claiming superior effect estimation.
- Historical test data were already inspected. The new code prevents further train/validation/test reuse, but cannot undo that past exposure; a genuinely fresh external/prospective evaluation remains desirable.
- Upstream imputation and feature timestamps, unmeasured confounding, positivity calibration, censoring assumptions for real-data IPCW, and the audit's P2 items remain limitations. This work does not establish clinical safety or causal identification.

Existing unrelated user edits and historical model/result artifacts were preserved. No remote training jobs, commits or deployments were performed.
